# Open HACCP Monitor

Open HACCP is a PHP 8.3/MariaDB backend, ESP32 sensor contract and mobile-first operational dashboard for temperature and humidity monitoring. The current prototype includes Sensor Protocol V1, three-device simulation, device onboarding, protected measurement-point photos, account themes, role-based users, persistent deviations, audit chaining, analyses and background-generated authority/extended exports.

It provides operational evidence, but it is neither legal advice nor a HACCP or instrument certification. The export profile must always be checked against the business, product and competent authority.

## Components

- Slim 4, PDO, MariaDB 10.11, Phinx and Monolog
- Argon2id users, database sessions, CSRF protection and three roles
- HMAC-protected device keys and a separate HMAC-chained audit log
- Sensor ingestion with partial ACKs, idempotent sequences and piggyback configuration
- Persistent temperature, battery, signal, offline, gap, rejection and firmware events
- PDF, streamed XLSX and zipped semicolon-CSV exports generated by a private worker
- Mobile-first ES-module dashboard with measurement-point photos and light/dark/system themes
- PHPUnit unit tests and real MariaDB integration tests

The public app is the only service with a host port. MariaDB, the export worker and the optional demo fleet remain internal. Export files live in `haccp-export-data` and expire after 24 hours. Protected photo variants live outside the webroot in `haccp-media-data`; job, photo-history and audit metadata remain in MariaDB.

## Local start

Requirements are Docker Engine with Compose v2, `openssl`, and a free local port (default `18082`). PHP and Composer are not required on the host.

```bash
cp .env.example .env
openssl rand -hex 32 # DEVICE_API_KEY_PEPPER
openssl rand -hex 32 # AUDIT_LOG_KEY, must be different
docker compose up -d --build app worker db
curl http://localhost:18082/health
```

Replace every placeholder in `.env`. `DASHBOARD_PASSWORD` must have 12–128 characters. The app waits for MariaDB and migrates automatically; the worker opens no public port. A manual migration is:

```bash
docker compose exec app vendor/bin/phinx migrate -e production
```

Open [http://localhost:18082/login](http://localhost:18082/login). On the first migrated start, `DASHBOARD_USERNAME` and `DASHBOARD_PASSWORD` bootstrap the only initial administrator. After that, the database is authoritative and changing those environment values does not overwrite users.

## Users and security

The roles are:

- `administrator`: users, operation profile, devices/settings, actions and every export.
- `operator`: dashboard, devices/settings, deviations/actions and exports, but no user or security administration.
- `auditor`: read-only dashboard and authority evidence; no mutations or extended exports.

Administrators create accounts with a one-time temporary password. A new user must change it before any other operation. Sessions contain a hash of a random 32-byte token, expire after 12 hours of inactivity or seven days total, and use an HttpOnly/SameSite-Strict cookie. Mutations require the session CSRF token. Five failed logins in 15 minutes temporarily lock the account. Deactivation and password reset revoke all sessions; users are retained for evidence references.

Emergency administrator recovery runs inside the app container:

```bash
docker compose exec app php bin/admin-reset --username=admin
```

The generated temporary password is shown once. Verify the append-only audit HMAC chain with:

```bash
docker compose exec app php bin/audit-verify
```

Never reuse `DEVICE_API_KEY_PEPPER` as `AUDIT_LOG_KEY`. Neither value may be rotated without a controlled migration/recovery procedure.

## Dashboard and analyses

The navigation contains **Übersicht**, **Analyse**, **Abweichungen**, **Exporte**, **Benutzer** and **Betrieb**. Active devices show temperature state, battery status and RSSI bars. Analysis supports 7, 30 and 90 days, device/point filters, temperature/humidity, event distributions, availability/connection quality and battery history.

On phones the four daily operational areas use a persistent bottom dock; account, theme and administrative pages are grouped under **Mehr**. Tables become labelled touch-friendly records, dialogs use the available screen width and all actions remain usable from 320 px without horizontal page overflow. Desktop retains the compact side navigation.

The selected measurement point can have a versioned equipment photo, for example the monitored refrigerator rather than the sensor electronics. Administrators and operators can take a photo with the rear phone camera or choose one from the media library; auditors have read-only access. The list uses a generated thumbnail and tapping it opens the protected full-size image and revision history. An administrator can permanently remove an erroneous/sensitive revision after entering the current password; the database retains only an audit tombstone and promotes the latest surviving revision.

JPEG, PNG, WebP, HEIC and HEIF uploads are accepted up to 12 MiB and 24 megapixels. ImageMagick corrects orientation, converts to sRGB, strips EXIF/GPS data and discards the original. Only a 2048-pixel WebP and 480 × 320 thumbnail are retained outside the webroot. Image URLs require an active dashboard session.

Every user selects **Hell**, **Dunkel** or **System**. The preference follows the account across devices; `System` responds live to the operating-system setting. The last browser value is mirrored locally to avoid a theme flash on the login screen. PDF and spreadsheet exports keep their fixed print-oriented styling.

Battery remaining days are explicitly an estimate. A forecast requires at least 20 values over seven days and a credible negative trend, considers at most 30 days from the current battery cycle, and is capped at 730 days. **Batterie gewechselt** starts a new cycle. Insufficient or unstable data is displayed as such.

Temperature thresholds are inclusive. State events open once on threshold violation and receive updated observations instead of duplicates; recovery sets `closed_at`. Offline is evaluated as `max(2 × upload interval, upload interval + 15 minutes)`. Battery uses configured thresholds and weak signal starts below −75 dBm.

The deviation workflow is `open → acknowledged → action_recorded → verified/resolved`. Cause, action, affected-product disposition, time and responsible user are required. Corrections append a new revision. Verification requires the current password; measurements, previous revisions and completed evidence are never overwritten.

## Operation and compliance profiles

Administrators maintain business identity, address, timezone, authority/reference number, retention and HACCP responsibility under **Betrieb**. Every measurement point has a versioned profile with:

- general DE/EU HACCP evidence or optional quick-frozen module;
- GHP, OPRP or CCP classification, purpose and responsible user;
- retention period;
- instrument maker/model/serial, conformity status and reference;
- separate calibration and verification references plus their dates.

Exports resolve device settings and point profiles as they were effective at measurement time. The quick-frozen profile enforces at least 12 months retention and only passes preflight when instrument evidence is documented. No EN conformity is claimed for the prototype without evidence.

## Export Center

`POST /api/v1/dashboard/exports` returns HTTP 202. The private worker processes queued jobs, retries a transient generation failure once, writes the file to `haccp-export-data`, calculates SHA-256 and expires the file after 24 hours. One job covers at most 366 days; a longer requested range is automatically divided into consecutive jobs of at most 366 days.

Two modes are available:

- **Behörden-Nachweis (Kernumfang):** business identity, points/purpose, effective limits and intervals, relevant temperature values, completeness, deviations, actions and checks. Battery, RSSI, Wi-Fi timings, firmware, batch/IP/user-email and audit internals are excluded.
- **Erweiterter Export:** selected operational fields such as humidity, battery, RSSI, Wi-Fi timing, sequences, receive time, firmware, transmissions and configuration history.

Measurement-point photos are intentionally excluded from both modes. They support dashboard orientation and are not part of the authority evidence dataset.

Formats:

- PDF: compact German report with daily summary and deviations, not a five-minute raw-value dump.
- XLSX: typed `Nachweis`, `Messwerte`, `Abweichungen`, `Datenqualität`; extended mode adds `Diagnose`, `Übertragungen`, `Konfiguration`.
- CSV package: ZIP with UTF-8 BOM and semicolon-separated `manifest.csv`, `measurements.csv`, `deviations.csv`.

Formula-like strings are neutralized before spreadsheet output. A failed preflight does not assert completeness: the output is prominently marked **Entwurf / Nachweis unvollständig**.

Detailed scope, legal framing and privacy boundaries are in [`docs/EXPORTS_AND_COMPLIANCE.md`](docs/EXPORTS_AND_COMPLIANCE.md).

## Device onboarding and Sensor Protocol V1

Use the plus button next to **Geräte**. Creation transactionally stores the device, first measurement point, initial thresholds and setup package. The plaintext 64-hex device key is returned once under `Cache-Control: no-store`; only its peppered HMAC-SHA-256 digest is stored.

On first boot, reference firmware exposes a WPA2 SoftAP `OpenHACCP-…`. Join it using the per-device setup password and open `http://192.168.4.1`. Candidate settings are not committed until the unit joins 2.4-GHz Wi-Fi, synchronizes UTC, verifies TLS CA chain and hostname, authenticates to the configured server and validates its configuration. See [`docs/DEVICE_PROVISIONING.md`](docs/DEVICE_PROVISIONING.md).

Firmware deployment must use:

```text
https://haccp.pow24.org
```

The sensor establishes Wi-Fi, UTC and certificate-verified HTTPS before HTTP/JSON exchange. Plain HTTP is only for the isolated Docker path and loopback development.

The stable device endpoints are:

- `POST /api/v1/device/measurements`
- `POST /api/v1/device/heartbeat`
- `GET /api/v1/device/config`

Successful measurement and heartbeat responses contain the complete current operational configuration, so a deep-sleep wake cycle can upload and adopt a newer schedule in one TLS connection. Diagnostic `errors` is an optional additive array of stable firmware codes. Existing V1 requests remain valid.

See [`docs/SENSOR_PROTOCOL_V1.md`](docs/SENSOR_PROTOCOL_V1.md), [`docs/FIRMWARE_CONTRACT.md`](docs/FIRMWARE_CONTRACT.md) and [`docs/FIRMWARE_IMPLEMENTATION_HANDOFF.md`](docs/FIRMWARE_IMPLEMENTATION_HANDOFF.md).

## Demo fleet

The optional profile provisions a refrigerator, freezer and milk-drink cooler. It uploads 12 historical values per unit once, then varies a value every five minutes. Keys, exact pending batches and counters remain only in `haccp-demo-state` and never in logs or Compose output.

```bash
docker compose --profile demo up -d --build
docker compose --profile demo run --rm demo php tools/demo_fleet.php --once --url=http://app
```

Reserved UIDs are `haccp-demo-fridge`, `haccp-demo-freezer`, and `haccp-demo-milk-cooler`. Only `haccp-demo-*` keys may be automatically created or rotated. VPS demo traffic uses the public HTTPS route.

## CLI and simulator

```bash
docker compose exec app php bin/device-create --uid=haccp-p01-0001 --name="Prototype A"
docker compose exec app php bin/measurement-point-create --device=haccp-p01-0001 --code=fridge-1 --name="Prototype fridge" --sensor-type=SHT45 --location="Kitchen"
docker compose exec app php bin/device-list
docker compose exec app php bin/device-regenerate-key --uid=haccp-p01-0001
docker compose exec app php bin/device-disable --uid=haccp-p01-0001
```

Exercise ACK and retry idempotency without exposing the key in command history:

```bash
docker compose exec -e DEVICE_KEY=PASTE_DEVICE_KEY app php tools/sensor_simulator.php \
  --device=haccp-p01-0001 --url=http://localhost --measurement-point=fridge-1 --count=3 --resend
```

The first upload reports accepted records; the immediate resend reports duplicates and creates no measurements.

## VPS deployment

The default bind is loopback-only `127.0.0.1:18082`. The VPS override joins only `app` to the existing external `proxy` network with alias `haccp-monitor`; Nginx Proxy Manager routes `haccp.pow24.org` to `haccp-monitor:80`, forces HTTPS and uses a public certificate. Worker, database and demo expose no public port.

```bash
docker compose -f docker-compose.yml -f docker-compose.vps.yml up -d --build app worker db demo
```

Before an upgrade, take a MariaDB backup. The persistent `haccp-media-data` volume must be included in the normal encrypted VPS backup alongside MariaDB. Apply additive migrations, then start the app and worker; no additional public port or Nginx Proxy Manager route is needed because authenticated photo delivery uses the existing HTTPS host.

## Tests

```bash
docker compose --profile test run --rm --build tests
docker compose --profile test down
```

The suite migrates an empty MariaDB database and verifies protocol limits/idempotency, diagnostics, device/config behavior, Argon2id, sessions/CSRF/roles, photo authorization/history/deletion, image variants and metadata stripping, account themes, compliance versioning, event lifecycle, audit integrity, analysis, exports and secret-free logs. Browser QA covers 320/375/430 px phones, desktop, role menus, photo upload/viewer, all themes, dialogs, keyboard access, reduced motion and horizontal overflow.

## Data and log safety

Logs contain request IDs, routes, status and aggregate results, never passwords, session/device keys, Wi-Fi credentials, image bytes, original photo names or full request bodies. Image EXIF/GPS data is removed before storage. Both export modes exclude photos. Device keys, database credentials, dashboard bootstrap password, the device pepper and audit key enter containers through Compose secrets.

Inspect service state without printing secrets:

```bash
docker compose ps
docker compose logs --tail=100 app worker
docker compose exec app php bin/audit-verify
```

## Legal basis used for the prototype

The product deliberately uses the term **Behörden-Nachweis (Kernumfang)** instead of claiming a universally complete statutory dataset. The design references Article 5 of Regulation (EC) No 852/2004, EU guidance 2022/C 355/01, Regulation (EC) No 37/2005 and German § 2a TLMV. Evidence scope and retention remain a business HACCP decision unless a specific profile imposes a minimum.

Firmware handoff ready: **YES** — Sensor Protocol V1, JSON Schema, OpenAPI and firmware contract use the same endpoints, limits, optional diagnostics and piggyback configuration semantics.
